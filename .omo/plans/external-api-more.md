## TL;DR (For humans)

<!-- Plain English for a non-engineer: NO file paths, NO todo numbers, NO wave/agent/tool names. -->

**What you'll get:** The extension's OpenAI-compatible local API server gets the missing agent powers: external programs can use the extension's built-in Skills/MCP/Function-Call tools on BOTH backends (web session and official API), their own tool tables are injected so the model actually knows about them, tool execution progress streams back live, images work on the official-API backend too, and the extension's own OpenAI/Gemini media analysis can be called through the same chat endpoint. The listen address (default localhost, optional 0.0.0.0) now really binds where configured, with a security gate + warning when exposing to the LAN. Model names (including the vision model) are discoverable, the "declared V4 Pro but actually got V4 Flash" bug is fixed and pinned by tests, and connection blips no longer kill model access (auto-restart of a dead server, dead-connection detection, in-flight request cleanup). The extension is renamed "DeepSeek++ More".

**Why this approach:** The relay/bridge/settings/test infrastructure already exists and covers half the wishlist. The plan closes gaps by reusing the existing bridge protocol (adding fields, never breaking shapes), keeping ONE authoritative model catalog and ONE config store, reusing the existing media-analysis pipeline instead of inventing a second one, and pinning every fix with contract tests so the reported regressions cannot return.

**What it will NOT do:** It will not change the Chrome Web Store or Firefox extension IDs (installed users would lose the extension), add any new persistence keys or second config authority, add new relay endpoints, touch the pi ecosystem pins or the stream-codec authority, or add mobile support.

**Effort:** Large
**Risk:** Medium - multi-surface change (TypeScript service + Rust relay + settings UI + rename); mitigated by existing contract tests and per-todo TDD.
**Decisions to sanity-check:** tool execution events ride the existing SSE delta as a new optional field (OpenAI clients ignore unknown fields); model catalog stays DeepSeek-only (OpenAI/Gemini media models are NOT advertised as chat models); rename keeps both store IDs; the LAN security gate blocks non-loopback binding until at least one API key is enabled.
